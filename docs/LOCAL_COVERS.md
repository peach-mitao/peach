# 本地封面匹配

## 范围

视频目录和图片目录通过现有的媒体目录设置登记。扫描会登记各层子目录中的图片；本地封面任务从已有 SQLite 图片记录建立一次任务级索引，不新增数据库表或常驻扫描器。

自动选择依次保留已有正式封面、读取 NFO 显式图片引用、查找同目录配套图片、选择跨目录唯一匹配，随后才允许在线补全。原始视频与图片只读，封面写入 Peach 已有的生成缓存。

## 身份与冲突

番号提取和作品身份使用现有编目规则。字母番号的数字前导零可归一；日期式番号的连字符与下划线保留身份区别，厂牌数字前缀只按已有别名规则处理。裸数字不作为 FC2 图片身份。

本地匹配识别文件开头的紧凑番号、版本标记和分卷，例如 `abw0232 标题.mp4`、`ABW-232r 标题.mp4`、`ABW_232_标题.rmvb`。标题可用空白、下划线、括号或中日韩文字边界分开；推广域名与官方交付片段沿用既有规则。多个不同番号不自动匹配，标题词内的字母数字不作为另一个番号；长字母后缀不交给文件清噪器猜测。本地封面维护入口只写生成缓存；统一馆藏资料采集也复用此规则，行为见下文「源码运行」。

明确的 `[高清]`、`【高清】` 前缀与 `! ` 装饰可省略；相同番号连续重复两次可合并。完整头部番号后的 `File.001`、`FILE 26`、`Episode-02`、`S Model 51`、`SPECIAL SP 01` 与 `WATER POLE 09` 属于标题序号。`FILE-026`、`MODEL-051`、`SP-001` 等独立编号仍参与身份冲突检查；未知前缀和标题中间的疑似番号保留人工确认。

只有 NFO 提供番号、账本与文件名都没有身份的维护安装，使用现有资产封面键显示图片。安装锁内会再次保护已确认的本地图，正在完成的在线下载不能覆盖它。

图片支持 JPG、JPEG、PNG 和 WebP。动图、无法完整解码的文件不作为封面。多个同级候选只有解码像素一致时才视为同一图片，否则记录冲突；不按文件顺序或分辨率猜测。

## 重试与报告

本地封面匹配独立于在线资料完成检查点。已经扫描、在线资料已完成或本地证据缓存为空的作品，可以再次尝试本地封面。

报告记录成功候选、冲突、无候选、无法读取及已有封面数量。维护入口默认只读；应用只安装经过验证的封面缓存，不写作品身份字段，也不修改媒体文件。

库健康与卡片共用正式封面键解析，同时认可已有视频抽帧；两者都不存在才计入缺封面。正式封面与抽帧仍是不同的图片来源，抽帧不能覆盖已确认的本地封面。

在源码工作树的 PowerShell 中运行。第一次输入实际 Peach 数据目录；报告保存在该数据目录的项目上下文中：

```powershell
$peachDataDirectory = Read-Host 'Peach 数据目录'
$peachAudit = Join-Path $peachDataDirectory 'state/project-context/local-covers-audit.csv'
& .\.venv\Scripts\python.exe -X utf8 .\scripts\match_local_covers.py --data-root $peachDataDirectory --report $peachAudit
```

核对 CSV 中的 `matched` 项后，重放这份报告。应用时重新核对番号、候选路径与 SHA-256，发生变化的项跳过，已有封面保留：

```powershell
$peachApplied = Join-Path $peachDataDirectory 'state/project-context/local-covers-applied.csv'
& .\.venv\Scripts\python.exe -X utf8 .\scripts\match_local_covers.py --data-root $peachDataDirectory --apply --plan $peachAudit --report $peachApplied
```

同名 JSON 给出按视频统计的各状态数量、实际安装数、图片索引构建次数和耗时。报告包含本机路径与来源哈希，须选用新的 CSV 路径，且不能放在媒体、数据库或生成缓存目录。多版本共用同一个封面键时共同判定，单项重试也核对其余已登记版本。图片索引每任务至多一份，相同候选的校验结果按任务复用；安装时再验证源文件哈希。非本地图片沿用隔离进程和读取超时。

单片更新只检查所选视频和共享同一封面键的已登记版本，不读取无关视频的配套文件或图片。共同检查版本时，进度仍对应本次选中的视频；尚无番号且没有本地身份的条目不为其他作品构建图片索引。

## 源码运行

资料采集与自动落库共用本地封面匹配的安全番号规则。已登记的有效番号优先；文件名可确认的番号通过既有字段归属机制补入空值，随后按当前来源链补标题、演员、内容标签与正式封面。无番号的本地证据在安全规则能够确认身份时重新读取，并重新开放对应资料检查点；已确认身份的完成项和预览检查点继续复用。来源冲突、用户拥有的字段与编号不明的文件保留复核边界。

缺内容标签时优先请求既有的标签来源；未取得有效标签则继续询问当前链上尚未尝试的其他综合索引，取到可用内容标签后停止额外查询。只有未收录原词的空标签候选不阻挡其他来源的有效标签，原词继续留在复核队列。目录类型、来源配置、字段归属和作品身份核验仍由现有策略决定。网络失败、地区限制和超时保留可重试状态；明确的未收录答复才进入缺失记忆。重复分段按来源与番号共用本趟答复，额外查询仍受任务预算和主机间隔限制。

`SKY` 与 `GACHI` 发行前缀使用现有无码来源链，能够继续查询 AVSOX。相似前缀、数字厂牌前缀与日期式分隔符保留各自身份。

HEYZO 的桥接查询采用至少四位的序号写法，来源返回的编号原样保留。账本编号和作品身份比较继续使用共享规则。

来源的常用日文同义词与合并类别投影到已有中文标签，保留人体部位与具体行为的区别；否定词和含义不明的类别继续保留原文复核。既有快照的词表补齐复用 `scripts/reproject_snapshot_tags.py`：先生成只读报告，再按来源并集补入缺少的标签，保留人工决定与隐藏状态。

在线补全复用已取得的来源快照。已登记的社区来源（含桥接来源）的封面地址经过番号身份核对后，统一交给现有图源与解码校验；社区图保持社区来源身份，冲突图不安装，JavDB 水印图仅用于比对。

桥接快照的图片地址中，空格按 `%20` 编码后参与图片地址校验与下载；来源快照保留原值。

定向重试缺封面项目时，封面步骤仍可复用七天有效期内的成功资料快照；过期快照不复用，缺失资料字段的强制重试继续重新查询来源。

## 验收

隔离测试覆盖跨根目录和多层子目录、大小写、任意数量的数字前导零、多图冲突、相同图像去重、特殊番号、NFO 与同目录优先级、已有封面保护、缓存与检查点重试、重复运行及源文件不变。

核心样例是一个目录中的 `ABW-232.mp4` 与另一个目录中的 `abw000000232.jpg` 自动关联。Windows 原生测试和真实库只读报告通过后，才执行生产缓存安装和源码入口切换。
