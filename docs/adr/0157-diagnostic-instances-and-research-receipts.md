# ADR-0157 随机诊断实例与研究快照回执

- 状态为已采纳
- 日期为 2026-11-11
- 关联 ADR-0110、ADR-0132 与 issue #592

## 背景

诊断需要按实例观察版本升级和受影响范围。研究快照需要串起本机准备、传输响应和维护者归档三个阶段，并在接收服务留存期内保存可分析样本。

## 决策

### 诊断实例

沿用版本统计与错误诊断开关。开启后自动生成随机 UUID，持久化到本机诊断选择文件。升级后准备首次诊断上报时补生成，已关闭选择继续生效。关闭时移除本机标识，再次开启生成新值。托盘和子服务通过文件锁共享同一值。

`diagnostic_instance` 进入日联系、错误事件和故障计数日志。研究继续使用独立的 `research_instance`。实例标识与程序版本共同用于升级路径和故障实例分析。统计说明使用实例及实例日作为单位。

浏览器故障增加浏览器品牌、主要版本和客户端系统大类，服务主机环境保留独立字段。

### 故障计数

计数日志带 `count_schema=2`，包含通过筛选和登记上限的全部发生次数，包括首次定位事件对应的发生。首次事件受每日事件上限控制，计数日志可以独立发送。统计按诊断键、实际 UTC 日和版本求和。

已有聚合文件在首次读取时转换已提交次数，补入过去仅由首次事件承载的一次。迁移标记使转换只执行一次。诊断键计算排除技术实例标识，使相同技术故障可以跨实例对应。

### 研究证据

研究上传格式为 6，同意范围版本为 5。上传格式与同意范围分别管理，已有格式 5、6 的有效开启记录沿用原研究实例和授权记录。手动标签及收藏标签限定为现有内容词表中的规范名称。接收检查再次核对词表。

每次准备记录随机快照编号、原始字节数、gzip 字节数、准备与投递状态，以及有界失败原因。发送事件携带相同快照编号和大小。每日参与日志附带当前授权、当前周的快照证据，关闭联系保持最小载荷。设置页显示快照编号、大小和传输状态。

HTTP 2xx 对应接收端接受请求。附件下载、字段校验和归档结果构成后续留存证据。紧凑 JSON 和标准库 gzip 保持现有实现，原始与压缩大小上限分别为 100 MiB、18 MiB。

### 维护者归档

`research_archive` 使用显式指定的私有目录和独立 SQLite 库，导入已下载的 gzip 原文。来源事件提供接收时间和研究实例 tag。每实例每 UTC 周保留接收时间最新的一份，同时间按内容摘要稳定定序。旧无实例附件按原文摘要独立计样本。

汇总按每实例最新周快照计算作品持有、评分直方图、偏好分组和覆盖分母。原始程序版本从 `payload.peach` 恢复。旧无实例样本使用独立分母。汇总写入固定私有文件。删除实例和留存清理默认预演，明确执行后处理归档库和生成的汇总。下载源文件由维护者另外管理。

### 接收端与发版

下次发行构建读取新错误 DSN。新版的定位事件、版本日志和计数日志实际接收验收后，停用旧错误密钥，切断旧客户端发送。密钥切换与组织计费额度分别核验。

错误项目和研究项目增加服务端地理信息清理规则，移除 `user.geo`。订阅周期、迁移时间和超额原因按接收服务实际证据记录。

## 升级与验收

- 旧诊断开启记录在准备首次上报时生成随机实例，已有诊断聚合按计数版本转换。
- 格式 5、6 的有效开启记录直接识别，保留原研究实例、授权记录、每日联系及每周传输次数。扩大研究数据类别或用途时通过预览重新同意。历史 schema 4、5 附件仍可导入归档。
- 回归覆盖关闭与重开、旧计数转换、浏览器字段投影、回执白名单、历史附件、幂等导入、并发去重和明确删除。
- 发版制品及接收端实际留存验收绑定下次发行，issue 保留开放状态。
